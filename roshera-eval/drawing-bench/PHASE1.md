  - **Section views** A-A / C-C / D-D with hatch (101, 105, 110, 120, 125) and **detail views** with circle + scale (105 detail C x4; 110 details A/B/C and section D-D; 120 sections A-A/B-B/C-C).

## 2. What the pipeline can and cannot produce

### Headless entry point (STEP -> sheet) [V]
- **Existing, no server needed:** `roshera-backend/export-engine/examples/step_probe.rs`. `cargo run -p export-engine --example step_probe -- <file.step> <out_dir> [max_drawn]` calls `ExportEngine::import_step_content` (production importer), then for each solid `draw_in_part_frame` -> `standard_drawing_auto` -> `verify_drawing` -> `render_drawing_svg`, one SVG per solid, with import diagnostics. This is exactly the phase-2 harness base. Limits: `standard_drawing_auto` only (no `?scale=`/first-angle variant, no title-block fill, no PDF/DXF, no sheet certificate); extend it (new example file, not the importer) to loop over ids, write SVG+DXF+PDF, run `certify_drawing`, dump `Drawing` JSON.
- **Server route:** `POST /api/geometry/import_step` (main.rs:10924) then `POST /api/parts/uuid/{uuid}/drawing` (registers a sheet; main.rs:11395+) or `GET /api/parts/{id}/drawing.svg?scale=` (one call). Then `GET /api/drawings/{id}/{svg|pdf|dxf|quality}` and `/semantic` readback. Core builder: `build_standard_drawing_off_lock` (api-server/src/drawing_mgr.rs:1381) -> `standard_drawing_auto_with_projection` / `standard_drawing_hlr_with_projection` (geometry-engine/src/drawing/dimensioning.rs:1518 / :700). Projection angle first/third supported (`ProjectionAngle`).
- Cheaper than the server for 49 parts: the example route (no auth, no async, no kernel server).

### What a standard sheet contains [V from code, dimensioning.rs]
- Views: FRONT, TOP, RIGHT (orthographic, HLR with hidden lines, centerlines) + shaded ISOMETRIC raster; A3 default up to A0, sheet auto-picked by max extent, scale auto-fit to standard ratios. Optional user-added views (bottom/left/iso/custom) via `POST /api/drawings/{id}/views`.
- **One** SECTION A-A, only when `drawing.hole_sites` is non-empty, cut plane chosen on a **world axis** (`choose_section_plane`, dimensioning.rs:3082; `attach_section_view`, :3369).
- Dimensions (`auto_dimensions`, :107): kinds `diameter`, `radius`, `extent`, `position`, `angle`, `length`, `pitch`, `pcd`, `location`, `hole_callout`, `chamfer`, `fillet` (R callout) from the analytic feature table (`readable::extract_dimensions`); round-part conventions (Ø outside, bolt-circle) in `round_part.rs`; hole stacks (THRU / counterbore / countersink / linear-rectangular patterns, "4x Ø6.60 THRU ⌴ Ø11.00 ↧ 6.80") in `hole_features.rs`; hole table (`hole_table.rs`); cutting-plane line with A labels.
- Notes strip: unit note + "GENERAL TOLERANCES: ISO 2768-m" (`Drawing::tolerance_note`). Title block ISO 7200-style with drawn_by/date/material/number/revision/sheet/approved_by/document type/supplementary title, mass label, `check_iso_7200` (title_block.rs).
- GD&T: `PlacedDatumSymbol`/`PlacedFcfBlock` are rendered **only from the part's GDT sidecar/DRF** (Task 6). An imported STEP has none, so its sheet has no datums/FCFs/tolerances unless a user adds them.
- Quality + truth: `verify_drawing` (layout collisions, annotation quality), `certify_drawing` / `SheetReadbackCertificate` (sheet vs live model, with refusal at export of an incomplete sheet), `answer_query` semantic readback. Exports SVG/DXF/PDF (svg.rs, dxf.rs, pdf.rs).
- SVG text hooks for a scorer [V]: `<text class="dim-text" data-dim-id>`, `hole-table-text`, `gdt-fcf-text`, `notes-strip`, `<g class="view" data-projection=...>`.

### Cannot produce (grep-verified: no hits in `drawing/` for detail, auxiliary, thread, balloon, BOM, surface finish, weld) [V]
No **detail views** (circle + enlarged view), no **auxiliary views**, no **multiple sections / offset or aligned sections / half sections** (one world-axis A-A only), no **thread callouts** (M12x1.75-6H, tapped depth), no **surface-finish / weld / balloon / BOM**, no **ordinate or baseline dimensioning**, no **dimension tolerances or fits** (+/-, H7/g6, limit dims) on auto sheets, no **broken views**, no **"TYP"/"ALL AROUND" note logic**, no **PMI import** from STEP AP242 (`GEOMETRIC_TOLERANCE`, `DIMENSIONAL_*` are not parsed; grep in `export-engine/src/formats/step` finds only unit handling).

## 3. Scoring method

Goal: turn "is the drawing good" into numbers that go up when we fix things. Three layers, from fully automated to looked-at.

**Layer A, automated, no reference needed (kernel truth).** Per part: sheet build succeeds in N seconds (`step_probe` already prints), `verify_drawing` issue count by kind/severity, `certify_drawing` verdict counts (omitted/stale/refused), views present, % of model features (cylinders, holes, blends, chamfers) the certificate says are represented on the sheet. This catches "omitted bores" without any reference image.

**Layer B, reference-assisted (the CADGenBench score).** Per part id 101-150 (49 parts):
1. **Looked-at extraction (vision/human, once per part, ~5 min each):** read `reference/<id>/input.png` (zoom into quadrants; Read shows it downsized, so crop/upscale with PIL in a scratch dir for dense sheets like 120) and write `reference/<id>/ref.json` using the schema in `score.py`: view kinds present, every dimension (kind, value, count, feature text), hole callouts (Ø, count, THRU/CBORE/CSINK/thread), notes, datums. This is **not automatable** with reliable accuracy on 3072 px rasters; budget human review for each.
2. **C0 reconstruction filter (automated):** the reference part is not the reconstruction. Before scoring, drop reference dimensions the reconstructed STEP's own geometry cannot contain: compare each reference value against the *set of all analytic dims `extract_dimensions` returns for that solid* (the ground truth of what that STEP has). A reference dim absent from the whole feature table is "reconstruction error", excluded from our recall; one present in the feature table but not on the sheet is "sheet omission", counted against us.
3. **`score.py`** (this folder): parses our SVG text and matches reference dims one-to-one on (kind, value) with tolerance max(0.05 mm, 0.5%); reports per part `dims.recall`, `wrong_kind` (right number, wrong class, e.g. a radius drawn as diameter), `missing`, `extra_on_ours` (precision proxy, informational; the reference is deliberately sparse in places and dense in others), hole callouts missing (and which of counterbore/thread is not stated), reference view kinds missing (section/detail/iso), notes missing, GD&T/tolerance counts. Run: `python -I score.py ours.svg ref.json`. Not run in this phase [I]: it was only syntax-checked.
4. **Headline per part** = 0.5 dim recall + 0.2 hole-callout recall + 0.15 view-kind coverage (front/top/right/iso/section/detail) + 0.15 Layer-A cleanliness (no verify errors). Report distribution over the 49, not just the mean; track the worst 10 and the "would a machinist accept" yes/no per part, below.

**Layer C, looked-at acceptance (per sheet, 1-minute check, binary + tag):** render our SVG to PNG next to the reference; for each sheet answer: (a) can a machinist make the part from this without asking questions (every feature sized and located, hole callouts complete)? (b) any lie (wrong value, dimension on the wrong feature, section through the wrong place)? (c) legibility: overlaps, leaders crossing, text on geometry, scale/sheet sensible? Record tags (missing-detail-view, missing-thread, clutter, wrong-view-orientation...) so gaps rank by frequency x severity. Layers A and B are regression-safe; C is for ranking and for the video.

**NIST pass (GD&T/tolerance):** for each of 11 models, apply the PDF's PMI through the GD&T/datum API, then check sheet contains the datum symbols, FCFs (symbol, value, datum refs), +/- tolerances on the right dimensions, and that `answer_query` returns them (it is the sheet-readback test). Score = items present and attached / items in PDF. Datums and FCFs from the sidecar are already rendered; the missing part is dimension tolerances (G6) and AP242 PMI import (G5).

## 4. First-pass prediction: 5 parts (reading code + references; no builds) [I]

Parts: 101 (prismatic cover, bores/cbore/csink/threads, section), 105 (pump housing, freeform cavity, details), 110 (thin bracket with pockets, many details), 120 (300 mm die-cast enclosure, ribs, 60+ dims), 125 (sheet-metal-like housing, ang/radius heavy).

Predicted gaps in impact order (what the reference shows and we do not emit):
1. **Detail views missing** (105 C, 110 A/B/C/D-D, 120 sections, 125). Pockets, small blends, rib spacing and thin-wall features at 1:1 in 3 views are illegible or unmeasured. Largest single miss on 3 of 5 parts. No code path exists.
2. **Section coverage** : we emit at most one world-axis A-A, and only when bores exist (`attach_section_view` early-returns on `hole_sites.is_empty()`). 105/110/120/125 need 2-3 sections through pockets/walls/cavities (and wall-thickness dims like "3.00", "1.50" in 125/120). Pocket-only or cavity parts get none. Depth/wall dims therefore missing.
3. **Hole callouts: thread / blind / csink variants** (101: "6 X M12x1.75-6H - 15 DEEP", "CBORE Ø35 5 DEEP", "CSINK Ø12 X 90"). `hole_features.rs` handles THRU / counterbore-on-through / countersink-on-through / equal-pitch grids; it explicitly does not claim a counterbore over a blind hole, chamfered exits, or irregular patterns (those stay table rows) and has no thread notion (a STEP carries a plain cylinder; the thread class has to be a user/agent annotation). Expect partial callouts; irregular patterns (101's 6-hole PCD plus 4 corner holes, 105's 4+2 mixed) end up in a hole table, which a reader accepts, but "4X" pattern/PCD stack on a non-round part is likely absent.
4. **Dimension coverage/selection on organic plates** (101 outline radii R10/R12/R18, Ø188/Ø200 arcs; 110 R10/R13.8/R15, 150.5 deg; 125 R50/R75/R90 chains, 47 deg/85.06 deg pattern angles). `auto_dimensions` is driven by analytic features per world-axis view; fillet/chamfer callouts are drawn only where the blend is in profile in a standard view (`shows_blend_profile`), `angle` only from recognised features, so slanted bosses, arcs not on world axes and curved-outline radii will be partial. Parts not aligned to world axes (a STEP's arbitrary orientation: `draw_in_part_frame` is only exercised for assembly-placed parts) may produce skewed "front" views and lost dims [I, needs a run to confirm].
5. **Density/legibility at scale** (120: ~60 dims; 125; 110): `compute_layout` stacks dimensions in bands (`dimension_band_gaps`, STACK) and collision-resolves; risk of overflow/overlap or dropped dims on dense parts, and performance (293-face gear once wedged the backend for minutes; `draw-profile` exists for this). Expect `verify_drawing` errors or truncation on 120.
6. **Tolerance/GD&T/datums absent on imported parts** (101 has datum A/B boxes; NIST set is all about this). The sheet shows only "ISO 2768-m", no per-dimension tolerances.
7. **Pictorial/ISO**: we have one shaded ISO; the references show 1-2 (105 has two orientations: outside and inside). Minor.
8. **Notes** ("TYP", "ALL AROUND", "BREAK EDGES", "R1 ALL AROUND") not generated: minor for the benchmark, noticeable for a machinist (default radii/edge-break note is the first thing they look for).
Things we do better than the references (keep, show in the video): verified certificate/stale-sheet refusal, true hidden lines via HLR, ISO 7200 title block with mass, ISO 2768 note, first/third-angle correct layout with alignment enforcement, projection-aligned views (the references deliberately scramble these), dimension edit that drives the part on Roshera-built parts (`drawing_edit.rs`).

## 5. Drawing TAB UX vs SolidWorks / Inventor / NX [V from `drawings-api.ts`, `DrawingsWorkspace.tsx`, `SheetPanel.tsx`, `drawing-overlays.tsx`; behaviour inferred]

Have: sheet size selector (A4-A0 + custom) and sheet list, **1st/3rd angle toggle** (drawing-overlays.tsx:242, `PATCH /projection`, re-lays-out views), add view from a preset list (front/top/right/bottom/left/iso/custom), remove view with undo, **drag a view** with projection-line constraint and kernel-side alignment resolution (`drawing-drag.ts`, `PATCH .../views/{id}`), per-view scale / hidden-line toggle / rename / position, zoom/pan/fit, **click a dimension to edit it, which drives the part** for recorded-history parts (and refuses honestly for imported ones), title-block card (drawn by, date, material, number, revision, sheet n of m, approved by, doc type, supplementary title), SVG/PDF/DXF export, drawing quality report, GD&T datum/FCF display from the model.

Missing vs what an engineer expects:
1. **Create-view workflow**: no model-view wizard with live preview, no *projected view from a chosen parent* (click-to-project in any direction), no **section view tool** (draw a cut line, pick direction, offset/aligned/half), no **detail view tool** (circle on a parent, scale, label), no **auxiliary view**, no **break/crop/broken view**, no **isometric/shaded-vs-wireframe/edges-only per view** selector.
2. **Dimensioning**: no smart-dimension tool (pick two edges/a circle to add a dimension), no baseline/chain/ordinate, no reference dimensions "(235)" (the 110 reference has them), no add-tolerance/fit (symmetric, bilateral, limit, H7), no dimension text editor (prefix/suffix: "4X", "TYP", "THRU", Ø/R/depth symbol insertion), no arrow/leader style, no **driven vs driving distinction** shown to the user, no drag of dimension text/extension offsets (verify).
3. **Annotation**: no free **note/leader** tool, no GD&T FCF add dialog on the sheet (datum/FCF come from the model-side GD&T flow), no surface-finish, weld, balloons, BOM/parts list (assemblies), revision table editing, centerline/centermark editing, hole-callout editing, hatch pattern/material editing.
4. **Sheet/format**: no sheet-format templates (company title blocks, logos, custom border), no zones editing, no sheet scale default per sheet, no multi-sheet export in one PDF (title block has sheet_index/count; confirm), no print setup, no layers/line-style table (ISO 128 line types exist in the renderer but not editable), no standard switch (ISO/ASME/DIN/JIS: dimension style, arrowhead, decimal comma vs point, hatch).
5. **Associativity feedback**: a "drawing is out-of-date" state exists via the sheet certificate; no rebuild/refresh button semantic equal to SolidWorks "Rebuild", no change highlighting between revisions (this is where Roshera's timeline/diff can beat the incumbents).
6. **Export**: PDF/DXF/SVG only; no DWG, no per-sheet export option set (paper size, scale, line weights), no 3D-PDF/PMI. DXF layer mapping/units not user-selectable.
Prioritise for engineers adopting: (1) section tool, (2) detail tool, (3) smart dimension + tolerance entry, (4) notes/leaders with "TYP/THRU" symbols, (5) sheet templates, (6) projection options per view. Dimension-drives-part is already a differentiator: expose it visibly.

## 7. Phase-2 plan

1. **Harness first (no kernel changes).** New example `export-engine/examples/drawing_bench.rs` (copy of `step_probe`; the step/tessellation dirs stay untouched): for each id read `output.step`, build the sheet (third angle, plus first angle once), write `ours/<id>.svg/.dxf/.pdf`, `Drawing` JSON, `verify` + `certify` summary, wall time per stage (`draw-profile`). Output `ours/index.json`. **Measure:** 49/49 built, time distribution, count of verify errors, certificate omissions. This gives the Layer-A baseline immediately with zero reference work.
2. **Reference extraction.** Vision/human `ref.json` for the 49 parts (start with 10 spanning sizes: 101,105,110,120,125 +5), C0 filter, run `score.py`, record baseline table in `baseline.md`. Calibrate parsing against our real SVG text (scorer was written against the SVG classes, not run).
3. **Fix order = biggest measured delta per effort,** expected: G3 (threads/blind/cbore claims; add the thread as an annotation channel, honest-refusal if unknown) and G4 (curved-outline radii, angles) -> G2 (multi-section) -> G1 (detail views) -> G6/G9 (tolerance text, TYP notes) -> G5 (PMI import, coordinate with the STEP-import stream) -> G7/G8. Each step lands RED-first with the benchmark metric as its gate: re-run the harness, report delta in recall, verify-error count, time.
4. **NIST track** in parallel to G5/G6: apply the PDFs' PMI via the GD&T API for the 11 models; score FCF/tolerance/datum presence.
5. **Volvo demo path:** pick 3 demo parts after the baseline; record the video from the app drawing tab driving first/third angle, a section, a dimension edit; keep the sheet-certificate "cannot lie" story (references deliberately violate standards; ours is standards-clean and certified).
6. **UX** (section 5) in parallel only after backend capabilities exist; the app is a thin display layer.

**Phase-2 resource estimate [I]:** the example builds in `export-engine` (pulls `geometry-engine`; first cold build ~12-20 min, 6-10 GB RAM peak in rustc for geometry-engine; use `-j 2`, `CARGO_PROFILE_DEV_DEBUG=false`, release or dev per the repo's "debug about equals release" memory). Free disk 25 GB recommended. Do not run while another kernel job holds the target-dir lock.
