Roshera Architecture Atlas

git rev 0857ca85 generated 2026-07-27 assembled from five verified mapper reports (backend, kernel, frontend, agent-layers, flows)

Roshera is an agent runtime for geometry, not a CAD tool in the traditional sense: the backend/SDK is the product and the React viewport is one thin client, with agents as the primary orchestrated actor and humans directing at a higher level. The system is built star-topology around a self-certifying B-Rep kernel that cannot lie — every mutating operation is checked against a nine-conjunct validity certificate computed fresh from geometry, never asserted. The governing discipline is honest refusal over silent wrong answers: operations outside a verified envelope return typed errors rather than approximations mislabeled as exact. Code is the ultimate truth; this document describes one revision and decays from there.

Star topology

geometry-engine is the sink every non-leaf crate reaches. api-server is the sole binary at the top, orchestrating everything with “no geometric logic” of its own. Arrows are verified dependency edges (crate→crate Cargo.toml deps, plus the three external clients calling api-server over HTTP/WS). shared-types, ros-format, and assembly-engine are leaves — zero intra-workspace dependencies of their own.

The certificate

ValidityCertificate — a nine-conjunct, geometry-derived soundness verdict recomputed on demand (never asserted from history) for every solid. Computed at geometry-engine/src/primitives/topology_builder.rs — BRepModel::certificate (~2642, hot path clones cache) / compute_certificate (~2687, private, always recomputes) / certify_solid (~2899, public wrapper).

Nine conjuncts — all required for is_sound()

1. brep_valid — validate_solid_scoped passes: Euler–Poincaré, manifold edges, pcurve references, orientation consistency, no degenerate/self-overlap faces.
2. watertight — tessellated mesh has zero boundary edges (manifold_report, chord 0.1, weld 1e-6).
3. manifold — every mesh edge borders exactly 2 faces.
4. oriented — every directed mesh edge traversed at most once — catches flipped-normal defects invisible to watertight+manifold alone.
5. self_intersection_free — coarse-chord (0.5) mesh self-intersection scan.
6. construction_consistent — linked source-sketch construction geometry stays co-located within a tolerance-band-expanded bbox (tri-state; only Inconsistent blocks soundness).
7. eyes_consistent — dual-eye render-free Truth↔Semantic cross-check: every RecognizedFeature must reference a live face and sit on the surface type its label implies; fails closed.
8. tessellation.clean — display-tessellation quality: no degenerate facets, normal agreement ≥0.98, analytic agreement ≥0.999, zero off-surface facets.
9. mesh_quality.clean — zero boundary-crossing facets, max normal deviation ≤40° (aspect-ratio and min-angle are reported, not gated).

Carried but excluded from is_sound()

  • labels_consistent — tri-state annotation-defect signal; annotation defects are not geometric defects.
  • model_debris_orphan_faces — a model-level fact (not this solid's fault), re-scanned on every certificate() call regardless of cache.

Memoization

Solid.cached_certificate: RwLock<Option<ValidityCertificate>> (solid.rs ~534). Lock is never held across the heavy compute: short read to check cache, compute lock-free, short write to store; last-write-wins, idempotent recompute.

Invalidation seams

  1. record_operation funnel (topology_builder.rs ~2472) — fires for every RecordedOperation input/output solid, even with no recorder attached (e.g. during timeline replay).
  2. SolidStore::get_mut backstop (~1840) — invalidates on any mutable borrow of a solid, regardless of call site.
  3. Sidecar self-invalidation — e.g. set_solid_construction (~2529).

Advisory 14-viewpoint dual-eye reconcile — separate from the gating certificate

The 14-viewpoint reconcile (api-server/src/reconcile_task.rs, VIEWPOINTS=14 at line 51) is advisory-severity and explicitly documented to never affect is_sound(). It runs off the write lock on an owned ModelSnapshot, fire-and-forget, capped at MAX_CONCURRENT_RECONCILES=2. It is distinct from conjunct 7 (eyes_consistent / TruthSemantic), which is synchronous, render-free, and is the one dual-eye axis that actually gates the certificate. render/viewpoint.rs (EYE-6, viewpoint-entropy best-view) is a separate on-demand selector, unrelated to the fixed 14.

Mass-properties provenance

MassPropertiesMethod is Analytical (exact divergence-theorem, planar solids) or Tessellated{rel_tolerance} (Tonon 2004, ≈5e-3 at fine tessellation). Each quantity (volume, center_of_mass, inertia) carries its own Exactness — Exact / Approximate{method, rel_error_bound} / Unavailable — independently, so volume can be exact while inertia is mesh-estimated. “The kernel never serves a mass-property number without it.”

Persistence

Tables

users, sessions, objects (per-session cache, PK (id, session_id)), permissions, tokens, api_keys (FK-free user_id by design — agent keys have no users row), timeline_events (durability log; FK-free; data JSONB = whole serialized TimelineEvent; sequence_number BIGINT is the replay key; indexed on (session_id, sequence_number)), durable_branches (branch metadata surviving restart).

Durability model

Append-only event log via api-server/src/durability.rs DatabaseEventSink::persist (one transactional row per TimelineEvent, written by TimelineRecorder's drain worker off the kernel's synchronous path). Boot replay loads all rows for a fixed single-tenant DURABILITY_SESSION_ID = "roshera-durability-main", ordered by sequence_number, then rebuilds the BRepModel by replaying events (recorder detached during replay). Quarantine: certify_rebuild re-measures soundness from a full trial replay; if a break or corrupt row is found, only the clean prefix is served, the break is named in logs and via GET /api/durability/status, and the tail is refused rather than silently served.

In-memory only

  • uuid_to_local / local_to_uuid ID maps (fresh UUIDs minted every boot)
  • consumed_uuids (undo tombstones)
  • solid_colors / solid_profiles (re-derived from the durable log at boot; the map itself is volatile)
  • reconcile caches, metrics, viewport_bridge state, transaction manager state, sketch/csketch sessions
  • the BRepModel itself — only durability path is a full event replay at boot, there is no snapshot

ROSHERA_DURABILITY=off behavior

Case-insensitive match on “off” yields a fully volatile scratch server: blank boot (no replay), all persist calls become no-ops, API-key rehydration is skipped entirely.

Auth model

Posture

AuthPosture::Required is the default — an empty environment enforces auth and returns 401 before any handler runs. AuthPosture::InsecureDevBypass activates only via ROSHERA_DEV_INSECURE=1|true, logs a loud warning every boot, injects a permissive sentinel AuthInfo (also bypasses the 100 req/min rate limit).

Schemes

Bearer <jwt> → validate_jwt; ApiKey <key> → validate_api_key. Both validated through the single session-manager AuthManager.

Key lifecycle

provision_api_key_handler (auth.rs:471) writes through AuthManager::provision_api_key; list (570) and revoke (605) are separate handlers. Keys are rehydrated from the durable api_keys table at boot (gated on durability_enabled), so keys and their revoked state survive a restart. No provisioning HTTP route beyond these handlers and no self-service revocation endpoint documented for agents.

Exempt paths

/, /health, /api/auth/login, /api/auth/register, /api/auth/refresh, /ws, /ws/*

WS auth

In-band Authenticate frame — the WS upgrade itself is exempt (browsers cannot set upgrade headers), so the client sends {'{'}type:'Authenticate', token{'}'} as its first message after onopen; the command surface is gated per-connection on that frame.

Known gaps & stale docs

The honesty section — every item below was directly verified against the tree at this revision, not inferred.

EventCertificate has no production producer
Evidence: timeline-engine/src/event_certificate.rs defines store_in(metadata); grepping the whole workspace shows store_in( is called exactly once, from the module's own #[cfg(test)] (event_certificate.rs:407). The only production consumer is the read-side from_metadata.
Implication: every real evidence-pack event's certificate field reads None and is served as null plus a certificate_absent_reason — evidence packs today carry no per-operation certificates for real activity.
timeline-engine's storage/ StorageEngine is dead code
Evidence: a file-based StorageEngine (event_log/index/snapshot) is defined in timeline-engine/src/storage but grep-confirmed never referenced outside its own mod.rs.
Implication: live persistence is entirely api-server/src/durability.rs (DatabaseEventSink) + session-manager::database — the storage/ module is inert.
Backend CLAUDE.md says 7 crates; the tree has 10
Evidence: roshera-backend/Cargo.toml workspace members list 10 crates including ros-format, verdict-harness, and assembly-engine, which the backend-local CLAUDE.md does not mention.
Implication: the backend-local documentation is stale relative to the actual workspace shape.
enforce_permission_layer's doc-comment describes a removed toggle
Evidence: the doc-comment on api-server's enforce_permission_layer still describes the ROSHERA_REQUIRE_AUTH soft/strict toggle; the code no longer reads that variable — scope checks are unconditional today.
Implication: anyone reading only the comment will believe permission enforcement is configurable when it is not.
.mcp.json carries no ROSHERA_API_KEY
Evidence: repo-root .mcp.json configures the roshera MCP server with env ROSHERA_URL=http://localhost:8081 and no ROSHERA_API_KEY.
Implication: this configuration only functions against a backend running with ROSHERA_DEV_INSECURE=1 — a dev-insecure assumption baked into the checked-in MCP config.
assembly-engine is fully standalone (zero workspace deps)
Evidence: grep-confirmed: assembly-engine's Cargo.toml pulls in only parry3d-f64 + serde, no intra-workspace crate dependencies, even though api-server depends on it.
Implication: an observation, not a defect — assembly-engine is architecturally decoupled and could in principle be extracted or reused independently.
Boot replay mints fresh UUIDs — identity is not preserved across a restart
Evidence: durability.rs boot_replay rehydrates events with their original ids/sequences into the timeline, but register_id_mapping mints a brand-new UUID per restored solid rather than reusing the pre-restart UUID.
Implication: any external reference to a solid's UUID from before a restart is invalidated by a restart. Documented as in-scope for Slice 1 durability, not yet closed.
No durability snapshots — every boot is a full event replay
Evidence: durability.rs has no snapshot mechanism; boot_replay always replays the entire timeline_events table for the durability session from scratch.
Implication: boot time scales with total history size; documented as acceptable for the current alpha stage.
Chamfer on closed (rim/seam) edges only supports the Plane–Cylinder face pair
Evidence: geometry-engine/src/operations/chamfer.rs:1118-1123 (chamfer_distances_for_closed_edge): if both adjacent faces are cylinders, or neither is, the function returns OperationError::NotImplemented(“...currently supports only a Plane-Cylinder pair in this slice”); the open-edge chamfer path is unaffected.
Implication: chamfering a closed rim edge between two non-plane-cylinder face kinds is refused today rather than attempted — a scoped gap, not a silent wrong answer.

Glossary

certificate
ValidityCertificate — a nine-conjunct, geometry-derived soundness verdict recomputed on demand for every solid; is_sound() requires all nine, with two further fields carried but not gating.
perception line
The compact sound/brep_valid/watertight/manifold/oriented/self_intersection_free/verdict/cert summary embedded in every mutating-operation response.
dual-eye reconcile
A cross-check between the kernel's own geometric Truth, a rendered Scene, and the labeled Semantic feature set along four axes; only TruthSemantic (conjunct 7) is synchronous and gates the certificate — the rest drive the async, advisory 14-viewpoint reconcile.
typed refusal
Returning a specific, named error rather than a generic failure or a silently-approximated answer, whenever an operation falls outside its verified envelope.
ratchet / KNOWN_REDS
A machine-readable allowlist of pre-existing failing tests; entries may only be removed once green and never added without a diagnosis doc. Currently empty.
red-gate
roshera-backend/scripts/red-gate.ps1 — the required pre-merge CI gate diffing the geometry-engine test suite against KNOWN_REDS.md.
timeline mould
Lets a parameter on a past event be overridden; incremental.rs then rebuilds only the downstream-affected dirty subtree rather than replaying the whole timeline.
quarantine
The durability state entered when boot_replay finds a corrupt/broken event row: only the clean prefix is served, the break is named, the remainder is refused.
workbench / bench
roshera-mcp's mechanism for toggling groups of MCP tool handles on/off to keep the live surface within an attention budget; never a capability gate since every tool remains reachable via invoke.
meta-funnel
The three always-on MCP meta-tools (find_tool, describe_tool, invoke) that let an agent discover and call any tool in the full registry through the identical validation/dispatch path a direct call uses.
evidence pack
GET /api/evidence-pack — bundles recorded operations with certificates-as-recorded, final mass properties, and the blackboard notebook, plus a separately-labeled live recompute.
blackboard
A backend-persisted, scope-partitioned shared notebook that both humans and agents read/write, backed by an append-only Add/Edit/Delete event log.
readable surface
geometry-engine/src/readable — described as the pillar that makes Roshera an agent runtime for geometry: wire records, dimensioning, feature extraction, and blackboard-claim verification exposed via /api/agent/*.
persistent id
A topological entity identifier intended to survive across operations/rebuilds so downstream references keep pointing at “the same” face/edge; landed for some paths, not yet universal.
bounded_exec
api-server's mechanism (Task #41) for running a heavy kernel op on a deep-cloned model in spawn_blocking under a per-op-class wall-clock budget, off the write lock.
